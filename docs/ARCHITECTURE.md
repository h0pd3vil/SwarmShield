# Architecture

## Responsibilities

Python remains authoritative for world state, logical ticks, random streams, observation generation, local tracks, UAV motion state, simulated communication, queue processing, deadlines, abstract task coordination, metrics, events, mission outcomes, and run artifacts. `swarmshield.session.SimulationSession` owns this state and advances exactly one existing engine step per `advance_tick()` call. The CLI runner now calls this same session repeatedly, preserving headless runs and batch experiments.

Godot 4 is the presentation and input layer. `main.gd` coordinates the shell and run lifecycle; `WorldView` draws selectable UAVs, backend geometry, planned waypoints, task regions, protection perimeters, and observation tracks; separate mission, team-metric, agent-inspector, event-timeline, and results panels format backend data. The synthetic satellite-inspired SVG supplies only muted ground texture. Roads, buildings, vegetation, water, parking, and tactical polygons are positioned from Python's map snapshot, so the visual features align with authoritative world geometry. Dynamic evaluator entity positions are not drawn as map contacts: contacts come only from actual local/shared tracks, with source and freshness indicated. Restricted-zone policies govern Python navigation and motion and emit boundary events. Entity-protection designations require a known fresh track, create backend monitoring tasks, and derive status from local evidence. The renderer offers independent optional overlays, zoom, pan, fit/reset, and map-coordinate selection. `World` has deterministic point/segment navigation and line-of-sight queries. Python can plan obstacle-aware routes with deterministic grid A*, follow waypoints under UAV kinematic limits, and replan after a blocked segment. Sensors use the current UAV position and heading for range/FOV checks and filter detections through configured LOS blockers. Bundled mission tasks are assigned and routed at run start by the baseline behavior policy. Godot requests ticks using a fixed timer interval and sends validated controls. It does not advance world positions or implement task/network rules. Rendering FPS does not determine logical ticks.

Python world coordinates are floating-point map units in `[0, world_width] × [0, world_height]`; positive X points right and positive Y points down, matching Godot screen coordinates. Entity motion, geometry, and future UAV paths use the same coordinate values. Logical ticks are discrete and have no implied duration in seconds.

## Process boundary

`game/scripts/python_bridge.gd` launches `game/python_bridge.py`, which adds the repository root to Python's module path and starts `swarmshield.protocol`. The parent process and adapter exchange UTF-8 newline-delimited JSON over standard input/output. Standard output contains only responses. Adapter diagnostics go to standard error.

Godot invokes `advance_ticks` from a timer whose interval is derived from the selected speed. Each request advances an integer number of engine ticks. The engine uses the existing deterministic independent RNG streams; pause and speed do not re-seed or change those streams. The same seed/configuration/intervention sequence therefore follows the same engine path regardless of render-frame frequency.

Protocol snapshots add mission metadata, live objective evaluations from the configured mission definition and current engine metrics, and validated spatial task definitions with per-run status records. A centralized baseline allocator assigns feasible tasks at run start and records `mission_task_assigned`. The session validates later task transitions, autonomously routes assigned UAVs, and evaluates actual route, local report, independent report, and sensor-footprint evidence. Spatial mission metrics are kept distinct from the existing abstract decision-task metrics; configured mission objectives remain the authoritative success rules. Unmet objective guidance is derived from the same actual metric/target comparison. Snapshots also report simulated communication availability, actual pending message endpoints, queue capacity, deadline urgency, and each track's source/confidence for map and inspector display. These presentation fields do not alter the headless runner's CSV snapshot schema or engine results.

Matched comparisons run isolated `SimulationSession` instances at the same configured seed for both treatments. A scheduler comparison holds cooperative/independent mode constant; a sharing comparison holds fixed-priority/EDF constant. The comparison service saves every treatment with the normal run-artifact writer and stores paired right-minus-left metric differences under `runs/comparisons/`. It does not alter the active session or introduce a second simulation implementation.

## Engine tick order

Each session tick keeps the existing runner order: expire overdue work; advance the world; advance each commanded UAV route once; replan a blocked route if an alternative exists; generate local observations from each current UAV pose and submit decision work; deliver due network messages; process scheduled work and apply completed decisions; advance abstract coordination and mission-task lifecycle; perform the second network delivery pass; evaluate partition recovery; record the render snapshot. At the configured horizon the session records pending work and computes its summary. `run_simulation()` loops over this same implementation, so the CLI and game do not maintain separate simulation rules.

## Current limitations

- UAVs move deterministically with acceleration, speed, turn-rate, battery, boundary and collision checks, and grid A* waypoint routing. The assigned-task behavior policy is centralized; grid resolution defaults to one world unit, so very narrow passages may be reported unreachable.
- The decision scheduler is one global queue, so its backlog is not an individual agent queue.
- Mission task transitions require recorded engine evidence. Coverage uses a deterministic geometric sensor-footprint grid and does not model detection probability.
- A partition is a global outage interval, not a spatial or peer-to-peer network topology.
- The Python protocol server handles one command at a time. Godot's bridge waits for each bounded response and reports a timeout if it does not arrive.
- Terrain is synthetic satellite-inspired artwork rather than georeferenced imagery. Optional fog shading uses coarse sensor-footprint cells from actual range/FOV/LOS checks; a source footprint is carried only with an observation report and becomes shared knowledge only after that report is applied. Coverage is presentation state and does not affect mission metrics or task decisions.
- Godot is optional: CLI, tests, dashboards, and experiment runners do not import it.
