# Terrain Map Upgrade

## Historical baseline

The initial audit and screenshot in [`module29-baseline.jpg`](images/module29-baseline.jpg) describe the map before this upgrade. At that point the static background contained roads that did not match Python geometry, the map had no camera controls, and restricted zones and protection were presentation gaps. Those findings are historical and are superseded by the current implementation below.

## Current map and simulation

- Python geometry is the source of truth for roads, buildings, vegetation, water, paths, parking, obstacles, safe areas, restricted zones, caution zones, and mission areas. The configured training map has 5 obstacles, 8 buildings, 6 roads, 2 paths, 2 parking areas, 1 water body, 5 vegetation patches, 4 safe areas, 1 restricted region, 1 caution zone, and 4 mission areas.
- Godot converts Python world coordinates to map coordinates for all dynamic geometry, vehicle poses/headings, routes, observation tracks, protection perimeters, and interaction. Pan/zoom transforms are inverted for map selection and destination input. Geometry is not independently generated by the renderer.
- The local SVG is an original synthetic satellite-inspired ground texture with muted crop/soil variation. It contains no roads or placed objects; those are drawn from the current Python snapshot so the illustration cannot introduce a second, misaligned road or building layout.
- Buildings use footprints and roof details; tree clusters, water, parking, road surfaces, and the quadcopter/contact sprites are recognizable but intentionally lightweight. This is stylized synthetic terrain, not real satellite imagery.
- UAVs and synthetic entities move from Python fixed-tick state. All four bundled survey tasks dispatch to separate UAVs. Raw evaluator entity coordinates are never shown as agent knowledge; map contacts come only from local/shared tracks and retain provenance and freshness.
- Deny-entry restricted polygons block unauthorized navigation and motion; `monitor`, `warn`, and `inactive` policies are configurable. Actual UAV movement emits boundary entry/exit, warning violation, or denied-entry events. An aircraft already inside a denied zone can leave.
- Entity protection requires a fresh known track and creates a configurable last-known perimeter plus a real monitoring task. Completion requires two separate local observations within its radius. Designation/removal and rejected commands are recorded as interventions and events; mission objectives and metrics use the task evidence.
- Map controls only affect rendering. Mission-area, caution, grid, sensor-range, shared-report, stale-track, and communication layers are optional. Communications default off and use only recent backend-confirmed events or current pending messages. Unselected task regions are faint; selecting a UAV emphasizes its task and dims unrelated tracks/routes. The map supports pointer zoom, drag pan, fit/reset, and zoom-to-selection.
- Optional fog shading uses 2.5-world-unit cells computed from each actual UAV sensor pose, range, heading/FOV, and LOS geometry. The source footprint is carried with each real observation envelope; a recipient records shared cells only after that report is applied. The map shades unknown, current local, earlier local, and shared cells and filters coverage to the selected UAV. These cells are presentation state and do not enter task assignment, mission objectives, or metrics.

## Remaining limitations

- Ground art is an original synthetic illustration, not georeferenced imagery. Building and vegetation artwork is simplified and the map has no GIS basemap import.
- Fog coverage uses a coarse 2.5-world-unit sample grid and is shown only when toggled on. It records sensor footprint, not guaranteed entity detection; configured detection probability still governs entity observations. Peer coverage is piggybacked on real entity-observation reports, so an empty sweep does not send an independent coverage-only message.
- The seed-42 demo did not produce a restricted-zone crossing, so no restricted violation was claimed from it. Unauthorized blocking and warning entry are covered in focused Python motion tests.
- Sensor coverage and entity protection remain synthetic deterministic mechanics; protection reflects local observation evidence within a configured radius, not a physical safety guarantee.
